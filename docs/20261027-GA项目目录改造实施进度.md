## 路径契约

### 项目身份

- `project_key()` 以项目根归一化路径（Windows 大小写、Unicode NFC）计算稳定 key；
- `ProjectRoots` 明确 project data、project/user/legacy workflow、global teams/tasks、legacy sessions；
- `RuntimePaths` 校验 project key、project data、project workflow roots 的一致性；
- session_start 记录 `original_cwd`、`project_root`、`launch_cwd`、`project_key`、`data_root`、`layout`；
- resume 从 session identity 恢复项目上下文，而不是根据当前 cwd 重新猜。

### 目标布局

```text
<DATA_ROOT>/projects/<projectKey>/<sessionId>.jsonl
<DATA_ROOT>/projects/<projectKey>/<sessionId>/subagents/
<DATA_ROOT>/projects/<projectKey>/<sessionId>/workflows/<runId>/

<DATA_ROOT>/workflows/<name>.json
<DATA_ROOT>/tasks/<projectKey>--<teamName>/
<PROJECT_ROOT>/.ga/worktrees/
```


### P7 迁移与 legacy 认领

新增/改动：

- `ga_cli/migrate_paths.py`
- `ga_cli/cli.py`
- `tests/test_path_migration.py`

CLI：

```text
ga migrate paths [--apply] [--kinds sessions,workflows,named,teams]
                 [--report] [--team-map OLD_LIST_ID=TEAM_KEY]
                 [--operator NAME]
ga migrate claim <session.jsonl> [--apply]
```

迁移语义：

- 默认 dry-run，`--apply` 才复制；
- 永不删除 legacy 源；
- 目标存在且 hash 相同 → `already_present`；
- 目标存在且 hash 不同 → `conflict`；
- tree 内任一冲突会阻止整棵 artifact 复制，避免半迁移；
- 批次 ledger 位于 `<DATA_ROOT>/migrations/batches/<signature>.json`；
- 报告含 UTC 时间、operator、mode、source/target、bytes、SHA256、status、conflicts；
- `claim` 只写旁路 `.claim.json`，原 JSONL 字节不变；
- named workflow 迁移只接受 `project` / `user` scope，未知 scope 直接报错。

完整迁移范围：

- session JSONL；
- `<sessionId>/subagents/**`；
- `<sessionId>/workflows/**`；
- 每个 workflow run 的完整 artifact（state/script/journal/agents/progress/final 等）；
- named workflow JSON。

team task 边界：

- legacy `temp/teams/<listId>` 没有可信 project identity；
- 未提供 `--team-map` 时只报告 `skipped`，绝不猜项目归属；
- 显式提供 `OLD_LIST_ID=TEAM_KEY` 后才复制到 `<DATA_ROOT>/tasks/<TEAM_KEY>`；
- 整个 legacy team board 源目录始终保留。

## 空白项目启动语义

**空白目录可以直接执行 GA，不需要预先创建 `.git`、`.ga`、`pyproject.toml` 或 `GA_AGENTS.md`。**

四个 marker 只用于一种增强场景：用户从项目子目录启动、且希望 GA 自动向上识别项目根。它们不是运行前提，也不是项目身份的认证条件。

规则如下：

- 当前目录本身没有上述 marker 时，当前目录就是项目根；
- 当前目录是空白目录、但父目录是 Git/GA 项目时，默认会识别父项目；若用户确实要把这个空白子目录作为独立项目，显式设置 `GA_PROJECT_ROOT` 指向它；
- `GA_PROJECT_ROOT` 与 runtime 已解析的 project root 是 authoritative 身份，使用 `project_key_exact()`，绝不因父目录有 `.git` 而漂移；
- `.ga/workflows`、`.ga/worktrees` 是按需创建的项目内目录，不是启动前要求；
- 真正的 git worktree 功能仍需要项目是 Git 仓库；这不影响普通主会话、subagent、workflow、Agent Team 或空白项目使用。

回归测试：`tests.test_ga_cli_launcher::test_blank_directory_is_a_valid_project_root`。

## 已知边界

- legacy 数据不会自动搬入当前项目；必须在明确项目上下文下显式 `ga migrate paths --apply`。
- 无 project identity 的旧 session 默认不进入项目 `/resume` 主视图，只在 `--all` 出现。
- team task 旧 `listId` 无法自动映射到 project；必须人工提供 `--team-map`，否则不复制。
- `GA_WORKFLOW_WORKSPACE_ROOT` 仍是最高优先级测试/嵌入覆盖；未设置时 workflow workspace 使用当前项目 data bucket。
- `TEMP_DIR` 仍是部分全局运行态的根（日志、hooks audit、MCP cache 等），不等于 session/workflow 的项目桶。
- 迁移报告、批次 ledger 和 claim sidecar 都是新增元数据；原始 legacy 文件不改、不删。
