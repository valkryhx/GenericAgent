# 中文输入法光标不跟输入框 —— 修好了吗

**日期：** 2026-11-16
**一句话：** 已经改好并通过真机验证。你按 `Ctrl+C` 退出后重跑 `ga`，切中文输入法就能看到效果。

---

## 你看到的是什么

你在输入框里打拼音时：

- 拼音（preedit）和候选框跑到**屏幕最下面**，不跟输入框里那个深色光标；
- 深色光标本身不横向扩展（它其实是一个只占 1 格的反显块，不随拼音变长）；
- 英文没事——因为英文不经过输入法，反显块自己看起来就是光标。

「左右晃」是同一件事的观感：你眼睛盯着一个位置（第 35 行第 9 列），拼音却画在另一个
位置（第 40 行最后一列），中间距离 4 行、110 列。

---

## 真正的原因

输入法的候选框和拼音**永远跟着「终端的原生光标」走**，而不是跟着 GA 自己画的那个
深色方块走。所以只要原生光标不在输入框里，拼音就一定画到别处去。

GA 有一段代码专门负责每帧把原生光标搬到输入框的光标位置（`stdoutCursorPark.ts`）。
这段代码的**搬运算术一直是对的**——我抓到了它真正发往终端的字节：

```
...\x1b[4A\x1b[10G
      ↑上移4行  ↑第10列
```

第 10 列正好就是输入框里光标该在的位置。

问题在「让光标可见」这一步。终端有一个开关（`ESC[?25h`）控制光标显示不显示。GA 的
代码里有一句注释说：「开了同步输出的话，光标全程都是可见的，所以只需要打开一次」。

**这句话在 Windows 终端上是假的。** Windows 终端（ConPTY）会在每帧的同步输出事务
边界上，自己把光标重新隐藏掉。结果就是：

- GA 以为光标一直是亮的 → 之后再也没发过「显示」指令；
- 整个会话里「显示」只发了 **1 次**；
- 在其余所有帧里，GA 都在**搬动一个看不见的光标**——位置对，但输入法找不到它；
- 输入法只好退回到终端的默认位置：屏幕右下角。

我实测到的数字：`show=1 / hide=2`，原生光标停在 `(39,119)`，而输入框的光标在
`(35,8)`。

---

## 改了什么

`frontends/ink/ui/src/stdoutCursorPark.ts` 里两行的改动：把「只在需要变可见时发送
显示指令」改成「**每一帧都发**」。

不会因此变闪。闪烁来自「隐藏 → 显示」成对翻转（每秒十几次），而这条路径上**一次隐藏
都不发**，每帧只有一次（幂等的）显示。

---

## 修好之后实测

用真终端（不是模拟）跑了三组配置，读回原生光标的真实位置：

| 配置 | 原生光标 | 输入框光标 | 结果 |
|---|---|---|---|
| 默认 | `(35, 9)` | `(35, 9)` | ✅ 完全重合 |
| 关闭同步输出 | `(35, 9)` | `(35, 9)` | ✅ |
| 关闭光标搬运（对照组） | `(39, 119)` | `(35, 9)` | ❌ 差 4 行 110 列 |

```
862 个自动化测试全部通过；类型检查干净。
```

## 顺带说明两件事

**一、之前那次「已经修好了」为什么没修好。**
`docs/ga_ui_ime_visible_native_cursor_root_cause_2026-07-16.md` 修的是「光标从来不加
显示」；那次确实改对了方向，但只加了「第一次显示」。这次修的是「只显示一次」。两次都
是同一个错误的两个实例：**把外部终端的行为当成已知常量写进了注释**，而那个常量是错的。

**二、GA 与 Claude Code 319 的差别在哪。**
CC 319 不依赖「记账」，它每一帧都把自己的光标声明（`cursorDeclaration`）连同可见性
一起提交给终端（`m0701:16319-16326`：`if (Te) ee.push({type: "cursorShow"})`，不带
「上次已经是可见的就不发」这种优化）。这次修复等价于把 GA 拉到同一个策略上。

   待确认项——park 生效时反显块其实可以关掉（CC 就不画反显块）。这属于观感问题，
   可以单独处理。
2. **还是跑屏幕下方。**
   请跑这一条命令把结果发我，它会打印原生光标与输入框光标各在哪：
   ```
   python tests/probes/python/_probe_park_config_matrix.py
   ```
3. **不用 Windows Terminal（比如 WezTerm / VS Code 终端 / conhost）。**
   我这次只在 Windows Terminal 上验证过。每帧重发显示指令在别的终端上是无害的，
   但我没有实测过「别的终端也会在事务边界隐藏光标」这个前提。
