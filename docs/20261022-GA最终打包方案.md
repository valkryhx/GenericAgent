# GA 最终打包方案（2026-10-22）

> 决策：采用 **A. `pip install` 后直接执行 `ga`**。
> Python 与 Node 由用户自行安装；发布物不内置运行时，不采用 PyInstaller / Nuitka / Tauri / Electron。

---

## 1. 最终交付物

```text
dist/
  genericagent-<version>-py3-none-any.whl
  genericagent-<version>.tar.gz          # 可选，用于审计/自行构建
  llm.yaml.example                       # 可见模板，便于离线查看
  install_release.ps1                    # Windows 安装与验收脚本
  SHA256SUMS.txt
  build-report.json
```

wheel 内包含：

- `ga_cli/`：console entry point `ga`；
- `genericagent/`：Python 运行时、workflow JS、只读 assets、内置 Skill；
- `frontends/ink/`：Ink bridge；
- `frontends/ink/ui/`：Ink UI 源码、`package.json`、`package-lock.json`；
- `frontends/terminal/continue_cmd.py`：Ink 的 `/resume` 依赖；
- `genericagent/resources/llm.yaml.example`：首次运行使用的只读配置模板。

wheel 内不包含：

- 真实 `llm.yaml` / `llm.yml` / `mykey.py` / `mykey.json`；
- `node_modules/`；
- Python / Node 运行时；
- tests、docs、temp、build 产物；
- Qt / Textual / Streamlit / pywebview / bot 运行依赖；
- 旧 UI 的默认依赖集合。

## 2. 用户环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Python | 3.10–3.13，推荐 3.12 | 用户预装；提供 `python` |
| pip | 随 Python | 通过 `python -m pip` 使用 |
| Node.js | 22.x LTS | 用户预装；提供 `node` |
| npm | 10.x | 随 Node.js 安装 |

安装器只检查这些运行时，**不会替用户安装 Python/Node**。

---

## 3. 构建

在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build_release.ps1
```

构建脚本会：

1. 清理本项目根目录下的 `build/` 和旧 release 文件；
2. 执行 `python -m build --wheel --sdist`；
3. 检查 wheel 必须包含 bridge、Ink UI 源码、workflow JS、资源和模板；
4. 检查 wheel 不含 `llm.yaml`、`mykey.py`、`node_modules/`、`__pycache__/`；
5. 把 `llm.yaml.example` 和 `install_release.ps1` 复制到 `dist/`；
6. 生成 `SHA256SUMS.txt` 与 `build-report.json`。

> 构建脚本会先清理本项目根目录下的 `build/` 和旧 release 文件，避免上一次的
> `build/lib` 把已删除或不应发布的内容带进新 wheel。

## 4. 安装

```powershell
powershell -ExecutionPolicy Bypass -File .\install_release.ps1 `
  -Wheel .\genericagent-0.1.0-py3-none-any.whl
```

脚本会：

1. 检查 Python、Node、npm；
2. `pip install --upgrade <wheel>`；
3. 通过已安装的 `ga_cli.__file__` 定位 site-packages 内的 `frontends/ink/ui`；
4. 执行 `npm ci --prefix <installed-ui-dir>`；
5. 检查 Python `Scripts` 是否在 PATH；
6. 运行 `ga --version`；
7. 首次创建用户 `llm.yaml`（已有文件绝不覆盖）；
8. 创建用户数据目录并打印真实的配置/数据路径。

安装脚本会先切到 wheel 所在目录，避免从 GA 源码仓库调用时，当前目录中的
`ga_cli/`、`frontends/` 抢先于 site-packages 被导入。

安装后启动：

```powershell
ga
ga ink
ga cli
ga list
```

`ga` 默认进入 React/Ink；`ga cli` 仅用于轻量排障。

## 5. `llm.yaml` 配置策略

### 5.1 查找优先级

安装版（wheel）按以下顺序查找：

1. `GA_LLM_CONFIG`：显式文件路径，最高优先级；
2. `%APPDATA%\GenericAgent\llm.yaml`：Windows 用户配置；
3. `%APPDATA%\GenericAgent\llm.yml`：兼容扩展名。

源码仓库（`genericagent` 的上层存在 `pyproject.toml`）仍保留历史行为：仓库根目录的
`llm.yaml` / `llm.yml` 优先于用户配置目录。判断依据是 **包安装位置**，不是用户当前工作区。
因此安装版在任意项目目录启动，即使该项目自身有 `pyproject.toml`，也不会被误判为源码 checkout，
更不会把运行数据写进用户项目。

### 5.2 目录约定

```text
当前工作区（用户的目录）:
  ga 启动时所在的目录
      # agent 工具、项目指令和用户文件的上下文根

用户配置（可编辑，升级不覆盖）:
  %APPDATA%\GenericAgent\
    llm.yaml
    mcp.json          # 可选

用户运行数据（可写，升级不覆盖）:
  %LOCALAPPDATA%\GenericAgent\
    temp/
      sessions/
      subagents/
      teams/
      model_responses/
    memory/
    assets/          # 首次从包内资源复制，不覆盖已有文件
    skills/          # 首次从包内资源复制，不覆盖已有文件

包内资源（site-packages，只读，升级时替换）:
  genericagent/resources/llm.yaml.example
  genericagent/resources/assets/
  genericagent/resources/skills/
  frontends/ink/ui/                 # Ink 源码与 npm 清单，不含 node_modules
```

`GA_DATA_DIR` / `GA_CONFIG_DIR` 可分别覆盖用户数据目录和用户配置目录；它们只影响 GA
自己的持久化位置，不改变 `GA_PROJECT_ROOT` 所代表的用户工作区。
`GA_PROJECT_ROOT` 由 `ga` 启动器设置为调用者当前目录；安装版不会把工作区切到
site-packages 或 `%LOCALAPPDATA%` 作为 Agent 的项目根。

### 5.3 首次运行与升级

- 用户配置不存在时，GA 把包内 `llm.yaml.example` 复制为
  `%APPDATA%\GenericAgent\llm.yaml`；
- 已有配置绝不覆盖，用户之后直接编辑该文件；
- 用户数据目录中的 `assets/`、`skills/` 只在文件不存在时补齐，已有文件不覆盖；
- 升级 wheel 不会修改用户 `llm.yaml`、记忆、会话或子代理状态；
- 包内资源和模板升级后可回退读取，但不会覆盖用户副本。

### 5.4 热重载

GA 按 `llm.yaml` 的 `mtime_ns` 判断是否重建会话。修改后可在下一轮对话或重启 `ga` 时生效。

### 5.5 `ga update`

- 源码仓库：执行 `git pull` 和 `python -m pip install -e .`；
- wheel 安装版：不会执行 `git pull`，只提示使用
  `python -m pip install --upgrade genericagent`；
- 升级后用户配置和用户数据保持原位。

## 6. 为什么不用其他方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| PyInstaller onefile | 不采用 | 用户自行安装 Python；onefile 会增加解压、资源和子进程路径复杂度 |
| Nuitka | 不采用 | 构建链重，跨平台成本高 |
| Tauri | 不采用 | 默认 UI 是 Ink 终端，不是 Web 桌面 |
| Electron | 不采用 | 体积大，仍需 Python sidecar |
| 纯 npm 打包 | 不采用 | 无法交付 Python 运行时和 bridge |

## 7. 验收标准

- `python -m build --wheel --sdist` 成功；
- wheel 内无敏感配置、`node_modules/`、旧 UI 依赖；
- 干净虚拟环境 `pip install <wheel>` 后 `ga --version` 成功；
- `ga list` 只显示受支持入口；
- `ga tui` / `ga gui` 返回 deprecated；
- wheel 安装目录中的 Ink UI 可执行 `npm ci`；
- 首次运行能创建用户 `llm.yaml`，且不覆盖已有文件；
- 升级后用户配置和用户数据仍在；
- `ga` / `ga ink` 均可启动，`ga cli` 可独立排障。
