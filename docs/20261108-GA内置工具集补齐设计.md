## 0. 一句话结论

GA 的工具**数量**（33 个）比 CC（22 个）多，但在三个地方有实质缺口：

1. **没有搜索类工具**（Glob / Grep），模型只能靠 `code_run` 自由拼 `grep`；
2. **`file_read` / `code_run` 的输出规模由它们自己决定**，不经过统一预算；
3. **退出码语义二值化**（`exit_code == 0` 即 success），`grep` / `diff` / `test` 的非零全被当成错误。

另外两项（写前必读、省略字节数可见）是体验与安全问题，排在其后。

本文先记录**现状事实**（第 1 章，逐条带代码坐标），再给**设计**（第 2 章），
最后是**实施与测试计划**（第 3、4 章）。实施严格按第 3 章顺序进行。

本次实施新增 `file_glob` 与 `file_grep`，合计 **34** 个。

### 1.2 没有 Glob / Grep

`assets/tools_schema.json` 中检索 `glob` / `ripgrep` / `rg` **零命中**。

现有替代路径只有两条，且都有问题：

| 替代 | 位置 | 局限 |
| --- | --- | --- |
| `file_read(keyword=...)` | `handler.py:314-327` | 只能搜**单个已知文件内部**，只返回**第一个**匹配，跨文件搜不了 |
| `code_run` 里自己写 grep | `handler.py:931` | 结果规模完全交给模型；`code_run` 在 `_EXEMPT_TOOLS` 里，**不吃预算** |

CC 的对应设计（调研文档 §10.1）：Glob 与 Grep 分开，`maxResultSizeChars` 分别是
100,000 与 **20,000**——「Glob 只回路径（短），Grep 回内容行（长）」。

### 1.3 工具结果预算：存在，但两个核心工具豁免

`genericagent/core/tool_results/budget.py` 已实现完整的「超限 → 落盘 → 头尾预览 →
`<persisted-output>`」链路，常量与 CC 对齐：

```python
DEFAULT_MAX_RESULT_CHARS   = 50_000     # budget.py:22
DEFAULT_PREVIEW_CHARS      = 2_000      # budget.py:23
DEFAULT_PERSIST_LIMIT_CHARS= 500_000    # budget.py:24
_EXEMPT_TOOLS = frozenset({"file_read", "code_run", "structured_output", "no_tool"})  # budget.py:29
```

`budget_tool_result()` 在 `loop.py:262` 被调用，**但 `file_read` 与 `code_run` 因
`_EXEMPT_TOOLS` 直接 `return content`**（`budget.py:171-172`）。

它们靠各自的内部截断兜底：

- `file_read`：`do_file_read` 里 `maxlen = 20000 // _tool_num`，
  再 `smart_format(result, max_str_len=maxlen, omit_str='\n\n[omitted long content]\n\n')`
  （`handler.py:1137-1138`）；单行超长另有 `L_MAX = min(max(100, 256000//realcnt), 8000)`
  的逐行截断（`handler.py:329`）。
- `code_run`：`maxlen = 10000 // _tool_num`（`handler.py:950`），
  传给 `code_run(...)` 的 `maxlen` 参数，由 `smart_format` 收尾（`handler.py:169`）。

**结论：不是"没有截断"，而是"各截各的，且都不落盘"。**
上限是硬编码的 20000 / 10000，无法通过 `GA_TOOL_RESULT_MAX_CHARS` 调整，
超限后也拿不到 `<persisted-output>` 与可回读的路径——模型看不到「另外 N 字节存到哪了」。

### 1.4 退出码语义二值化

`handler.py:161`：

```python
status = "success" if exit_code == 0 else "error"
```

`grep` 无匹配返回 1、`diff` 有差异返回 1、`test` 判断为假返回 1——在 GA 里全是
`status: "error"`。调研文档 §16.1 第 5 条把它列为 P0，理由是「模型最常见的误判来源」。

`smart_format` 也在这里被用来收缩输出（`handler.py:169`），
默认 `omit_str=' ... '`（`handler.py:354-357`），**不告诉模型省略了多少**。

### 1.5 写前必读：只在提示词里劝，没有强制

`assets/tools_schema.json` 的 `file_write` 描述写着：

> Before overwriting an existing file, read it first (file_read) so the overwrite is
> based on its current content

但 `do_file_write`（`handler.py:1090-1123`）**没有任何校验**：直接
`open(path, 'w')` 覆盖。`_read_dirs`（`handler.py:307`）只记录**目录**，
且仅用于 `file_read` 找不到文件时的相似文件名提示（`handler.py:345`），
与写前校验无关。

对比 CC（调研文档 §16.3 第 16 条）：写前必须读过 + 区分「读过全部」+ mtime 变了
但内容相同则放行（`m0591:73595`）。

### 1.6 路径安全层：只覆盖 workflow 子 agent

`genericagent/workflow/path_acl.py` 是完整的、纯函数的路径 ACL，已处理：

| # | 项 | 改动点 | 风险 |

### 2.1 `file_read` / `code_run` 纳入统一预算

**做法**：把它们从 `_EXEMPT_TOOLS` 移除，改为在 `limits.py` 按 CC 的语义注册
**每个工具各自的上限**，让 `budget_tool_result` 统一处理落盘与预览。

| 工具 | 上限（对齐 CC） | 依据 |
| --- | --- | --- |
| `file_read` | 不设上限（走全局 50,000） | CC 的 Read 用默认 `maxResultSizeChars` |
| `code_run` | 30,000（上限 150,000） | 调研文档 §1.1 表：Bash 是 `Pft()`（默认 30,000，上限 150,000） |
| `file_glob` | 100,000 | 调研文档 §10.1 |
| `file_grep` | 20,000 | 调研文档 §10.1 |

**保留内部截断，但改成"先粗后细"**：

- 内部截断（`maxlen`）继续存在，负责**性能**（不要把 500MB 文件读进内存）；
- `budget_tool_result` 负责**上下文安全**（落盘 + 预览 + 可回读路径）。

两者的分工必须写清：内部截断是「不读这么多」，预算是「读了但只给看这么多」。
`file_read` 现在的 `smart_format` 调用（`handler.py:1138`）改为不再收缩，
让预算统一处理——否则会发生二次截断，模型看到的是「被截断的截断」。

**兼容**：`GA_TOOL_RESULT_MAX_CHARS` 等环境变量继续生效（`budget.py:173-175`）。

### 2.2 退出码语义化

**新增模块** `genericagent/core/exit_codes.py`：

```python
def classify_exit_code(tool_name: str, command: str, exit_code: int) -> str
```

返回 `"success" | "error" | "informational"`。规则对齐调研文档 §2.11：

| 命令 | 非零含义 | 归类 |
| --- | --- | --- |
| `grep` / `rg` | 1 = 无匹配 | informational |
| `diff` | 1 = 有差异 | informational |
| `test` | 1 = 判断为假 | informational |
| `find` | 1 = 部分目录不可读 | informational |
| 其余 | ≥1 = 真错误 | error |

`code_run` 返回值里的 `status` 字段按此分类；`[Status] Exit Code: N` 行同时补一句
人类可读的说明（例如 `(grep: no matches)`），让模型不必自己推断。

**只对 bash/shell 类型生效**：`python` 类型保持 `exit_code == 0` 的语义，
因为脚本的返回值没有公认约定。

### 2.3 `file_glob` 与 `file_grep`

**为什么分两个而不是一个**：结果规模差 5 倍（100,000 vs 20,000），合并会让
「只想要文件名」的调用也背上内容行的预算。CC 分开是有理由的。

#### `file_glob`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `pattern` | string | 必填 | glob 模式，如 `**/*.ts` |
| `path` | string | 省略 | 搜索根目录，省略用 cwd |

- 硬上限 **100 个文件**（对齐 CC `U7o()`）；
- 输出只回路径，一行一个；
- 截断时明确写 `showing first 100 of N matches`。

#### `file_grep`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `pattern` | string | 必填 | 正则 |
| `path` | string | 省略 | 搜索根目录 |
| `glob` | string | 省略 | 文件过滤，如 `*.py` |
| `output_mode` | enum | `content` | `content` / `files_with_matches` / `count` |
| `ignore_case` | bool | false | `-i` |
| `context` | int | 0 | 前后各 N 行 |
| `head_limit` | int | 250 | 最多返回多少条/行 |

- 优先调用 `rg`；不存在时回退到 Python 实现（`os.walk` + `re`）；
- `rg` 路径探测：`shutil.which('rg')`，找不到再试 Git 安装目录；
- 结果上限 20,000 字符走预算层。

**两者都加入 `loop.py` 的 `_PARALLEL_SAFE_TOOLS`**（只读、无 handler 状态）。

**`path_acl.py` 需要更新**：`READ_TOOL_NAMES` 加入这两个工具名，
否则 workflow 子 agent 用它们能绕过工作区边界。

### 2.4 写前必读（强制）

**新增模块** `genericagent/core/read_before_write.py`：记录「哪些文件被完整读过」。

数据结构：

```python
@dataclass(frozen=True)
class ReadRecord:
    path: str          # realpath
    mtime_ns: int
    size: int
    complete: bool     # 是否读到了文件末尾
```

在 `file_read` 成功返回时登记（`handler.py:339` 附近）。判定规则对齐 CC：

| 情况 | 结果 |
| --- | --- |
| 从未读过该路径 | **拒绝**，返回「先 file_read」 |
| 读过但 `complete=False`（只读了片段） | **拒绝**，返回「读完整」 |
| 读过且 mtime/size 未变 | 放行 |
| mtime 变了但内容 sha256 相同 | 放行（并刷新 mtime） |
| mtime 变了且内容不同 | **拒绝**，返回「文件已被外部修改，请重读」 |

`file_patch` 同样适用（它比 `file_write` 更依赖「看到的 old_content 是当前的」）。

**逃逸口**：`file_write` 的 `mode=append` / `prepend` 不要求先读（追加不需要旧内容）；
新文件（不存在）不要求先读。

### 2.5 `smart_format` 省略量可见

当前（`handler.py:354-357`）：

```python
return f"{data[:max_str_len//2]}{omit_str}{data[-max_str_len//2:]}"
```

改为在两段之间写明确的数量：

```
… [12345 chars omitted] …
```

数量按 UTF-8 字节与字符都报（CC 报字节，模型对字节熟悉）：

```
… [12,345 chars / 13,201 bytes omitted; full output not persisted] …
```

若结果已经被预算层落盘，则提示路径而不是「not persisted」。

**步 3（省略量）**
- 10,000 字符输入、`max_str_len=100` → 文案里的数字等于实际省略量

**步 4（搜索）**

- `ignore_case` / `context` / `head_limit` 生效

**步 5（写前必读）**
- 未读就 `file_write` → 拒绝，错误信息含 "file_read"
- `file_read` 后写 → 放行
- 读后改文件（外部）→ 拒绝
- 读后 touch 但内容不变 → 放行
- 新文件 → 放行
- `append` 模式 → 不要求先读

## 6. 待确认（已核实，结论如下）

### 6.1 `_get_abs_path` 与 `path_acl.py` 是否语义一致 → **基本一致**

主 agent 的 `_get_abs_path`（`handler.py:919-924`）在有 `workspace_root` 时走
`resolve_workspace_child(path, root)`（`workflow/workspace.py:271`），后者做了
`(workspace / relative).resolve(strict=False)` 再 `relative_to(workspace)` 校验，
符号链接无法逃逸——与 `path_acl.canonical_workspace_path`（`path_acl.py:53`）
的 `realpath` + 前缀判定等价。

差异：`resolve_workspace_child` 对 `.`/`./` 有特判（返回 workspace 根），
`path_acl` 没有。不影响安全语义。

**结论：本设计不擅自统一两者**，只要求新增的 `file_glob` / `file_grep`
同时登记进 `path_acl.READ_TOOL_NAMES`，避免子 agent 用它绕过边界。

### 6.2 `code_run` 的 bash 类型在 Windows 上的实际执行器 → **是 PowerShell，不是 bash**

`handler.py:88-90`：

```python
elif code_type in ["powershell", "bash", "sh", "shell", "ps1", "pwsh"]:
    if os.name == 'nt': cmd = ["powershell", "-NoProfile", "-NonInteractive", "-Command", code]
    else: cmd = ["bash", "-c", code]
```

**这是一处必须在设计里明确的既有事实**：Windows 上请求 `type=bash` 得到的
其实是 PowerShell。对本设计的影响：

- 退出码分类不能只按「命令名是 grep」判断——在 Windows 上真正执行的是
  PowerShell，`grep` 可能压根不存在，退出码含义完全不同；
- 因此第 2 章的 `classify_exit_code` 必须**接收实际执行器**作为入参，
  在非 bash 执行器下退回保守的 `error` 归类。

该行为本身是否应该改变（Windows 上 `bash` 真的调 Git Bash）属于另一个议题，
**本设计不改它**，只让退出码分类对它安全。

## 7. 实施结果（2026-11-08 完成）

### 7.1 新增模块

### 7.2 改动的既有文件

| 文件 | 改动 |

### 7.5 一处行为变更需要知晓

**写前必读会拒绝一批现有用法。** 模型若习惯「不读就覆盖」，现在会收到：

> `target.txt has not been read in this session. Call file_read on it first so the
> write is based on its current content.`

这不是缺陷而是本设计的目的（见 §2.4）。但上线后如果发现有高频误伤，
应优先检查是不是「读片段就覆盖」被拦——那是正确拦截，不是误伤。

`append` / `prepend`、新建文件、以及 mtime 变了但内容 sha256 未变的情况
都不拦，已覆盖在测试里。
