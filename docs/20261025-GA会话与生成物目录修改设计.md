## 1. 目标与非目标

### 1.1 目标

| # | 目标 | 验收判据 |
| --- | --- | --- |
| G1 | 会话按「用户项目」分桶，`/resume` 默认只列当前项目的会话 | 在 A、B 两个目录分别启动 GA，各自只看到自己的会话 |
| G2 | workflow 运行数据、产物、隔离子 agent 工作区同样按项目分桶 | 同上，A 的 run 不出现在 B 的 `/workflows` |
| G3 | 工具 cwd 与 `workspace_root` 统一为**用户项目目录**，模型写出的相对路径落在用户项目 | 在项目 A 里让 agent 写 `notes.md`，文件出现在 A/notes.md |
| G4 | 「项目身份」只有一个来源：显式 `GA_PROJECT_ROOT` > 启动目录 | 不再出现会话 `cwd` 记录为 `frontends/ink/ui` 的情况 |
| G5 | 已有数据无损迁移，旧路径仍可读（只读兼容期） | 迁移脚本幂等；迁移前后 `/resume` 条数一致 |
| G6 | 全局数据（记忆、技能、模型配置、日志）保持全局，不进项目桶 | 两个项目共用同一份 `memory/` |

### 1.2 非目标

- 不改造前端 UI，不改变 `/resume`、`/workflows` 的交互形态（只改数据来源）。
- 不引入 SQLite / 数据库层：仍用 JSONL + 目录（GA 现有事实）。
- 不复制 CC 的「会话内嵌 projectDir 的恢复优先级」全部细节（GA 只需记录 + 校验，见 §5）。
- 不清理 `temp/` 下与本次无关的模块（bot 媒体、MCP 缓存等只做路径统一，不做功能改造）。

## 2. 目标目录模型

沿用调研 §2-§4 的「两层」思想，但把 GA 的**数据根**与**用户项目**彻底分开：

```text
<DATA_ROOT>                                  ← GA 自己的运行时数据根（与安装位置无关）
├── projects/
│   └── <projectKey>/                        ← 按用户项目分桶
│       ├── <sessionId>.jsonl                ← 主会话转录（= 现 temp/sessions/*.jsonl）
│       ├── <sessionId>/
│       │   └── subagents/
│       │       └── agent-<id>.jsonl         ← （预留）子 agent 独立转录
│       ├── workflow-runs/<runId>/           ← 现 temp/workflow-runs/<runId>
│       ├── workflow-store/                  ← 现 WorkflowStore 全部内容
│       ├── workflow_child_agents/<runId>/<jobId>/   ← 现 temp/workflow_child_agents/...
│       └── model_responses/                 ← 会话对应的模型原始响应
├── logs/                                    ← 跨项目日志（原 temp/ 下零散日志）
│   ├── ink_bridge_backend.log
│   ├── reflect_logs/
│   ├── hooks/
│   └── mcp_logs/
├── media/                                   ← 前端媒体与状态（原 temp/discord_media 等）
├── mcp/                                     ← mcp_tools_cache.json
├── memory/  skills/  assets/  （不变）
└── temp/                                    ← 过渡期只读旧位置（§8），不再写入
```

**用户项目目录 `<PROJECT_DIR>`**：

```text
<PROJECT_DIR> = realpath(GA_PROJECT_ROOT)  若显式设置
              = realpath(启动时 cwd)        否则
```

工具 cwd、`workspace_root`、模型写相对路径全部以 `<PROJECT_DIR>` 为根。
这与 CC 的行为一致（调研 §4.3）：**CC 的产物就是落在用户 cwd，CC 自己只占 `~/.claude`。**

## 3. 关键决策（含备选与理由）

### 3.1 决策一：数据根 = `user_data_dir()`，与安装形态解耦

| 方案 | 说明 | 评价 |
| --- | --- | --- |
| A. 保持 `RUNTIME_ROOT = PROJECT_ROOT if 源码 else user_data_dir()` | 现状 | ❌ 源码跑时数据写进 GA 仓库 `temp/`，用户项目 A/B 共用一个桶，G1 无法达成 |
| **B. `DATA_ROOT = GA_DATA_DIR or user_data_dir()`（推荐）** | 任何形态都在用户数据目录 | ✅ 与 CC「config home 与 cwd 无关」一致；源码跑也安全 |
| C. `<PROJECT_DIR>/.ga/` | 数据放进项目目录 | ❌ 污染用户仓库、需要 `.ga/` 进 `.gitignore`、跨机器迁移麻烦；CC 不这么做 |

**推荐 B。** 源码开发者如需旧位置，用 `GA_DATA_DIR=<repo>/temp` 显式指回去（等于保留旧行为，可回滚）。

### 3.2 决策二：`projectKey` 编码方式

| 方案 | 例（`D:\work\a-b` / `D:\work\a_b`） | 评价 |
| --- | --- | --- |
| A. 照抄 CC：非字母数字→`-`，>200 截断+hash | `D--work-a-b` / `D--work-a-b`（**撞车**） | ❌ 需要调研 §3.6 那套撞车检测才能用 |
| B. 路径编码 + 短哈希后缀 | `D--work-a-b-3f9a1c` / `D--work-a-b-7e02d4` | ✅ 可读 + 无撞车 |
| **C. 与 A 同款清洗，但**总是**追加 `-<sha256(realpath)[:8]>`（推荐）** | `D--work-a-b-3f9a1c` | ✅ 最简单，撞车概率 2^-32 量级 |

推荐 **C**：

```python
def project_key(path: Path) -> str:
    real = os.path.realpath(path)
    slug = re.sub(r"[^A-Za-z0-9]", "-", real)[:80]
    digest = hashlib.sha256(real.encode("utf-8")).hexdigest()[:8]
    return f"{slug}-{digest}"
```

- 可读前缀（≤80）便于人工排查，哈希段保证唯一；
- Windows 路径大小写：先 `os.path.realpath()` 再**按平台折叠大小写**（`os.name == "nt"` 时 `.lower()`）
  后再算哈希，保证 `D:\X` 与 `d:\x` 同桶；
- 与 CC 示例行为不同处：**始终带哈希后缀**，因此不需要 §3.6 的撞车检测流程（检测仍可作为
  迁移脚本的自检项）。

### 3.3 决策三：`PROJECT_ROOT` / `RUNTIME_ROOT` / `TEMP_DIR` 的处置

现状两种根混用，是「产物进 GA 仓库」的根因（调研 §5.3）。修改后：

| 常量 / 函数 | 修改后语义 | 备注 |
| --- | --- | --- |
| `PROJECT_ROOT` | **用户项目目录**（= 决策 §2 的 `<PROJECT_DIR>`） | 保留常量名（外部引用面太广），但语义落定为「用户项目」，不再等于「GA 安装目录」 |
| `PACKAGE_ROOT` / `is_source_checkout()` | 不变 | 「GA 装在哪」只用于找资源 |
| `RUNTIME_ROOT` | 保留为 `DATA_ROOT` 的别名（deprecated），文档标注 | 先不改名，避免一次性大改 |
| `TEMP_DIR` | 过渡期保留（只读旧位置）；新写入全部走新 API | 见 §8 |
| 新增 `DATA_ROOT` | `user_data_dir()`（决策 §3.1） | 所有运行时数据的唯一根 |
| 新增 `PROJECTS_DIR` | `DATA_ROOT / "projects"` | |
| 新增 `project_dir()` / `project_key()` / `project_data_dir()` | 见 §4 | **业务模块只用它们，不准再自己拼路径** |

### 3.4 决策四：工具 cwd 与 `workspace_root`

- 主会话：`GenericAgentHandler(self, self.history, str(paths.PROJECT_ROOT), workspace_root=str(paths.PROJECT_ROOT))`
  （改 `core/app.py:1046`）。
- 系统提示（`core/handler.py:2332-2333`）改为如实描述两个目录：
  ```
  cwd = <PROJECT_DIR> (./; 用户项目目录，工具读写与产物都在这里)
  agent data = <DATA_ROOT>/projects/<key> (会话/日志，不写用户文件)
  ```
- `handler.py:69` 的 `cwd = cwd or str(paths.TEMP_DIR)` 改为 `cwd or str(paths.PROJECT_ROOT)`。
- `code_run` 子进程环境 `GA_CODE_RUN_ROOT`（`handler.py:112`）继续指 `PROJECT_ROOT`——现在语义正确。
- 子 agent（`child_agent.py:971,990`）保持 `cwd=parent.task_dir`（隔离工作区），但默认
  `task_dir` 放到 `project_data_dir()/workflow_child_agents/...`。

### 3.5 决策五：`/resume` 与 `/workflows` 的可见范围

| 列表 | 默认 | 可选 |
| --- | --- | --- |
| `/resume`（会话） | 仅当前 `projectKey` | 命令开关「全部项目」，按 projectKey 分组展示 |
| `/workflows` | 仅当前 `projectKey` | 同上 |
| 子 agent / 团队视图 | 仅当前 `projectKey` | — |

与 CC 一致（CC 的 resume 列表就是按当前 projectDir 读取，调研 §3.5）。

### 3.6 决策六：项目名覆盖（**未实现**，保留为预案；见 §10 Q5）

提供 `GA_PROJECT_NAME`（对应 CC 的 `CLAUDE_CODE_PROJECT_DIR_NAME`）：

- 须匹配 `^[A-Za-z0-9_-]{1,64}$`，拒绝 `con/prn/aux/nul/comN/lptN`（照抄 CC 的校验，调研 §3.4）；
- **仅在设置了 `GA_DATA_DIR` 时生效**（对应 CC「仅 CLAUDE_CONFIG_DIR 设置时才认」），
  防止单机用户误设导致两个目录合并；
- **状态（2026-10-25 定）**：本期不实现。自动生成的项目标识已足够辨认，真正的痛点是「看不懂桶名」，
  用 `/projects` 视图显示项目真实路径解决，不改存储规则；将来若实现，显示名放桶内 `project.json`，
  key 不变、改名不动目录；
- 生效时 key = `<GA_PROJECT_NAME>`（不加哈希，因为名字是用户显式声明的）；
  若同名但 realpath 不同 → 记录告警并使用 `<GA_PROJECT_NAME>-<hash>`。

## 4. API 变更（`genericagent/paths.py`）

### 4.1 新增

```python
def project_dir() -> Path
    """用户项目目录：GA_PROJECT_ROOT（显式）> 启动目录快照（CLI 注入）> cwd。realpath 后缓存。"""

def project_key(path: Path | None = None) -> str
    """<project_dir> 的稳定桶名：清洗前缀 + '-' + sha256(realpath, 平台折叠大小写)[:8]。"""

def project_data_dir(path: Path | None = None) -> Path
    """DATA_ROOT / 'projects' / project_key(path)。不自动 mkdir。"""

def projects_dir() -> Path
    """DATA_ROOT / 'projects'。"""

def logs_dir() -> Path          # DATA_ROOT/'logs'
def media_dir() -> Path         # DATA_ROOT/'media'
def mcp_state_dir() -> Path     # DATA_ROOT/'mcp'

def ensure_project_dirs(path: Path | None = None) -> Path
    """mkdir project_data_dir()/子目录：model_responses、workflow-runs、workflow_store、workflow_child_agents。"""

def legacy_temp_dir() -> Path
    """旧位置（GA 仓库 temp/ 或 RUNTIME_ROOT/temp），只读兼容期使用。
    下线规则见 §10 Q4：跨 2 个 minor 版本或新结构发布满 6 个月即停读；到期先告警一个版本。"""

def session_project_dir(session_meta: dict) -> Path
    """由会话元数据（session_start.cwd / 显式记录）解析该会话所属项目桶；
    跨项目 resume 后工具 cwd 与 workspace_root 都以它为根（§10 Q3）。"""
```

**启动目录快照**：`ga_cli/cli.py` 在 `os.chdir(ui_dir)` **之前**把 `cwd` 写入环境变量
`GA_LAUNCH_CWD`，桥进程据此得到「用户是在哪启动的」，不受 UI chdir 影响（修调研 §5.5）。

### 4.2 语义变更

| 符号 | 变更 |
| --- | --- |
| `PROJECT_ROOT` | 语义从「GA 所在仓库（源码）/ cwd（wheel）」统一为「用户项目目录」 |
| `SESSIONS_DIR` | 保留为 `lambda: project_data_dir()` 语义（或只导出函数 `sessions_dir(project=None)`），默认值从 `TEMP_DIR/'sessions'` 改为项目桶 |
| `TEMP_DIR` | 标记 deprecated；新代码禁止引用 |

>
> - **工作区（workflow 中间文件、隔离子 agent 工作区）**：留在项目桶
>   `<DATA_ROOT>/projects/<key>/workflow-runs/`、`…/workflow_child_agents/`。
>   它们是 GA 私有运行时资源（供编排/重试/清理），不是模型要交给用户的产物；

>   用户项目（`paths.PROJECT_ROOT`）；也可用 `GA_WORKFLOW_WORKSPACE_ROOT` 把整个工作区

> 而 CC「产物在项目里」源于 CC 的 agent 工具 cwd 就是用户 cwd，GA 的 workflow 工作区
> 与之不同。默认在用户项目里建目录会带来 git 噪音、gitignore 负担和被误删的风险。
> 故 `default_workspace_root()` 的默认值定为 `paths.project_data_dir()`；将来若要改默认，
> 只需改这一个函数的返回值，调用方不动。

## 6. 迁移：旧 `temp/` 数据怎么处理

### 6.1 旧数据在哪、属于哪个项目

旧会话文件本身带 `session_start.cwd`（`transcripts.py:107-117`），但可能被 Ink 的 chdir
污染成 UI 目录（调研 §5.5）。所以迁移按以下判定：

```text
对每个 temp/sessions/session_*.jsonl：
  c = 首行 session_start.cwd（缺失 → 视为未知）
  if c 存在 且 realpath(c) 是合法的用户目录（不是 GA 的 frontends/ink/ui）：
        → 归入 project_key(c)
  elif c 缺失或为 UI 目录：
        → 归入 _legacy（<DATA_ROOT>/projects/_legacy/）
```

`_legacy` 桶在 `/resume` 的「全部项目」视图里显示为「旧会话（未归属）」，用户可手动认领
（认领 = `mv` 到对应 projectKey）。

### 6.2 迁移脚本（新文件 `tools/20261025-migrate_project_layout.py`）

| 步 | 动作 | 幂等性 |
| --- | --- | --- |
| 1 | 扫描旧根：`<repo>/temp`（源码形态）与 `RUNTIME_ROOT/temp`（wheel 形态） | 只读扫描 |
| 2 | 计算每个会话的目标桶；生成 `migration-plan.json`（含 source、target、reason） | 可重复生成 |
| 3 | **默认 dry-run**；`--apply` 才 `os.replace`（同盘）或 `shutil.copy2`（跨盘）。**源文件一律保留**，由用户确认后再手动删 | 目标已存在同内容 → 跳过 |
| 4 | `model_responses/`、`workflow-runs/`、`workflow_child_agents/` 按 **mtime 所在会话/run 的元数据**归桶；无法判定 → `_legacy` | 同上 |
| 5 | 写 `migration-report.json`（移动数、跳过数、`_legacy` 数、失败清单） | 覆盖重写 |
| 6 | 旧目录**不删除**：成功后写 `temp/migration-report.json` 与 `temp/.migrated-to-<DATA_ROOT>` 标记；应用启动时对旧目录只做只读兜底 | — |

原则：**不删用户数据**；迁移只做「复制 + 校验 + 标记」，旧 `temp/` 的清理交用户手动
（`docs/20261013-ga-workflow-隔离目录清理方案.md` 的守卫式删除可复用）。另：第 3 步虽写了
`os.replace`，但第 6 步要求旧目录保持完整——**若采用「源保留」策略，第 3 步一律用 copy2**，
`os.replace` 仅在用户显式加 `--move` 时启用。

### 6.3 兼容读（只读期，建议 2 个版本）

- `list_sessions()`：先读当前项目桶 + 旧 `temp/sessions`（可按 `cwd` 过滤到当前项目）；
- `restore_agent_session` / `load_session`：按路径打开，旧路径照常能读；
- 新会话只写新位置；`temp/` 不再产生新文件（`ensure_runtime_dirs` 不再建 `sessions`）。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| P4 改变工具 cwd，既有用户脚本依赖「相对路径落在 temp/」 | 模型旧习惯失效 | 系统提示显式区分 `cwd` 与「数据目录」；`GA_TOOL_CWD=temp` 回退开关；文档公告 |
| 旧会话 `cwd` 被 Ink 污染，迁移无法归桶 | 部分旧会话进 `_legacy` | `_legacy` 可见、可认领；迁移报告逐条给原因 |
| 项目桶数量增长（每个用过 GA 的目录一个桶） | 磁盘/`ls` 变大 | 项目桶本身很小（jsonl + run 目录）；提供 `ga projects list/prune` 后续命令（非本设计必做） |
| 跨盘迁移（`os.replace` 失败） | 迁移中断 | 跨盘走 copy2 + 校验；逐文件幂等；报告记录断点 |
| `realpath` 在 Windows 短路径/网盘上抛错 | key 不稳定 | 与 CC 一致：realpath 失败回退 `os.path.abspath` |
| 两个 GA 进程同时启动迁移 | 竞态 | 迁移靠文件锁（`DATA_ROOT/.migration.lock`）；应用启动**绝不自动 apply**，只读兼容 |
