## 2. 发现并修复的 2 个真 bug（goal 提案审批面板）

两处都在 `frontends/ink/ui/src/App.tsx`，导致"模型提议目标"时的一键审批框显示异常：

1. **面板完全不渲染**：`activePanel` 表达式的面板列表里漏了 `goalProposalPanel`。
   因为 `inputChromeSections` 只在 `hasPanel`（= `activePanel`）为真时才产出 `'panel'` 段，
   于是即便 `goalProposalPanel` 状态被事件设上，底栏也永远不渲染 `GoalProposalPanelView`。
   键盘处理（Enter/Esc/Down）却仍按隐藏状态生效——**用户完全看不到审批框，盲按 Enter 会直接
   批准设定目标**。对照：工具审批 `approvalPanel` 在列表里，两者本应对称。
2. **面板被裁到只剩标题+条件**：`panelRows`（决定底栏高度）同样漏了 `goalProposalPanel`，
   没有用到已存在的 `goalProposalRows()`。于是即使补了第 1 点，面板高度按 0 计算，
   `approve/reject` 选项和执行提示被裁掉。

修复：把 `goalProposalPanel` 加进 `activePanel`，并在 `panelRows` 里优先用
`goalProposalRows(goalProposalPanel)`（并补 import）。纯前端 5 行改动。

> 说明：这两处是本次 UI 测试新增的真实渲染帧测试才暴露出来的——此前 `goalProposalPanel.test.ts`
> 只测纯函数、`App.test.ts` 没有提案面板的渲染用例，所以一直没被发现。

## 3. 测试如何构造（可复现）

- 渲染帧测试（`src/goalUiRender.test.ts`）：用 `ink` 的 `render(<App startBridgeClient=假客户端/>)`
  挂载真实 App，假客户端按脚本注入 `goal_metadata` / `goal_nudge` / `goal_proposal_request`，
  捕获 ANSI 帧并 `stripAnsi` 后断言屏幕文本；键盘交互通过假 stdin 发送 `\r` / `\u001b` / `\u001b[B`
  并断言 App 真正发出了 `goal_proposal_response` 命令。
- 真实 e2e（`scripts/real_ink_goal_ui_e2e.ts`）：起真实 bridge 子进程 + 真实模型，真实键入
  `/goal` 与任务指令，断言真实渲染帧里出现 `Goal active` 与 `✓ Goal met`，并核对模型确实
  创建了带标记的文件、且无帧超出终端宽度。
- 运行方式：
  - 渲染帧：`cd frontends/ink/ui && node --import tsx --test src/goalUiRender.test.ts`
  - 全量 UI：`npm test`；类型：`npm run typecheck`
  - 真实 e2e：`node --import tsx scripts/real_ink_goal_ui_e2e.ts`

## 4. 顺带修的测试脚手架问题

`tests/real_goal_phase4_propose_e2e.py` 依赖外部已设 `GA_PROPOSE_GOAL_ENABLED=1` 才能跑通
（否则 propose_goal 因总开关默认关闭而被拒，9 项里 7 项失败）。这不是产品 bug，而是测试
不自包含。已在测试的 `setup_env` 里显式设 `GA_PROPOSE_GOAL_ENABLED=1`，使该 e2e 独立可复现
（9/9）。产品默认仍是关闭（不打扰用户），不受影响。
