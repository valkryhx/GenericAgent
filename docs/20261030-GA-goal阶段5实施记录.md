## 2. S0 元数据（`goal_metadata` 事件）

字段对齐 CC `Mqr`（m0696:378-400）：`condition / iterations / set_at / tokens_at_start / last_reason`，
并额外派生 `tokens_spent`（= 当前 token 位置 − 起始位置）与 `met`（活动目标恒为 false）。

- 通道：`hook_emit({"type":"goal_metadata","goal":{...}|null})`；无 `hook_emit`（headless）时静默。
- 去抖：只有 `condition/iterations/set_at/tokens_at_start/last_reason` 变化才推；**纯 token 增长不推**。
- 清除：推 `{"goal": null}`；若为达成/失败，附带 `terminal:{met,failed,iterations,tokens,durationMs}` 供前端渲染徽标。

### 2.1 会话级累计 token 计数器（对齐 CC `Th()`）

CC 卡片/终态里的 `tokens` 是 `costLedger.totalOutputTokens()`（m0017:4936 `Th()`），
即**整个会话累计的输出 token**，不是最近一次请求的上下文规模。

- `genericagent/llm/core.py`：`BaseSession` 新增 `session_output_tokens`；在唯一的用量
  归一化点 `_record_usage()` 里累加 `normalized['output_tokens']`。这与既有的
  `cache_stats.record_usage()` 求和口径一致，且 `messages` 流是
  `message_start`(output=0) + `message_delta`(final) 两个事件，也是求和而非覆盖，故不会重复计数。
- `genericagent/core/app.py`：`_goal_token_position()` 优先读 `backend.session_output_tokens`，
  缺失时回退到最近一次请求的 `output_tokens`（旧后端兜底，绝不静默为 0）。
- `tokens_spent = 当前累计值 − 设目标时的快照`，即 goal 生命周期内真实消耗的输出 token。

## 3. S1 只读卡片

- 与 `WorkflowStatusBarView` 同属底部状态带，**不是弹窗、不抢焦点、无按键**。
- 两行：`◎ Goal active · running {dur} · {N} turns · {tokens} tokens` + `Goal: {...} · Last check: {...}`。
- 达成/失败：`✓ Goal met · ...` / `✗ Goal failed · ...` 一行徽标；idle 时显示，running 时隐藏。
- 无 goal 时不渲染，`goalRows=0`，布局与游标计算完全不受影响（`layoutMetrics.goalRows` 默认 0）。

## 4. S2 遥测（本地优先）

- 文件：`<data_root>/logs/goal_events.jsonl`（append、UTF-8、LF、每行一个 JSON）。
- 事件：`goal_set / goal_cleared / goal_achieved / goal_failed / goal_met / goal_proposed / goal_proposal_decided`。
- 字段：`{event, at, origin?, iterations?, durationMs?, tokens?, reason_len?, met?, outcome?, ask_user?}`；
  **绝不写 condition/reason 正文**（只记 `reason_len`）。
- 开关：`GA_GOAL_TELEMETRY` 默认写本地；`off/0/false/no` 关闭。best-effort，不抛异常。

## 5. S3 nudge（默认关）

- 一行建议：`用 /goal 设定一个目标 —— GA 会一直工作到它达成`，显示在输入框下方 hint 区（`✦` 前缀），`Esc` 关闭。
- 门禁（`should_nudge`）：feature 开 && 无 active goal && relevant && 距上次 ≥ 冷却会话数。
- 默认 `GA_GOAL_NUDGE=0`（不开）；冷却默认 `GA_GOAL_NUDGE_COOLDOWN_SESSIONS=3`；状态落 `<data_root>/goal_nudge_state.json`。
- 会话开始时由 bridge 调一次 `goal_nudge.evaluate()`；关时不写状态文件。
