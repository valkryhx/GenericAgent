# GA `/goal` 只设目标不起回合（0 turns / <1s / 无产物）修复记录

日期：2026-11-03
症状复现输入：

```text
/goal d:\git_codes\GenericAgent\bug\goal_tests 在这个目录里面写一个8皇后一个解的html展示
```

界面只显示：

```text
Goal set: ...
Goal active · running 0s · 0 turns · 0 tokens
Worked for <1s
```

文件没有生成，模型没有实际工作。

---

## 1. 根因

`GenericAgent._handle_slash_cmd()` 里 `/goal <condition>` 分支原来：

```python
self._handle_goal_command(_gm.group(1) or '', display_queue)
return None
```

`GenericAgent.run()` 看到 `raw_query is None` 就直接：

```python
if raw_query is None:
    self.task_queue.task_done(); continue
```

也就是把 `/goal` 当成"已就地处理完的本地命令"，**从不进入模型回合**。
`_handle_goal_command()` 的 set 分支又只往 display_queue 发了一条终结性的
`{'done': 'Goal set: ...'}`。两件事叠加 → 只设置目标、立即结束回合，
于是 0 turns、<1s、无任何产物。

之前的真实 LLM e2e 大多是"先 `/goal` 设目标，再单独发一条任务"，
正好绕过这条路径，所以没暴露。

---

## 2. 对照 Claude Code 303 的正确语义

- `/goal` 命令定义（m1247）：非交互 `type:"local"`，`thinClientDispatch:"post-text"`。
- 命令执行（m2146 `At`）：设置成功后返回
  `{ type: "query", value: "Goal set: <cond>", prompt: qVn(cond) }`——
  即**设置完立刻发起一个 query（模型回合）**，不是本地结束。
- kickoff 文案（m0274 `qVn`）：

```text
A session-scoped Stop hook is now active with condition: "<cond>". Briefly
acknowledge the goal, then immediately start (or continue) working toward it —
treat the condition itself as your directive and do not pause to ask the user
what to do. The hook will block stopping until the condition holds. It
auto-clears once the condition is met — do not tell the user to run `/goal clear`
after success; that's only for clearing a goal early.
```

CC 的 `shouldQuery` 默认为 true（m0120 `H6e`：`mode==="prompt" && shouldQuery!==false`），
所以 kickoff 这条用户消息会真正触发回合。

## 3. 修复内容

### 3.1 核心：`genericagent/core/app.py`

1. `_handle_slash_cmd()` 的 `/goal` 分支改为把 kickoff 提示作为本轮用户消息返回：

```python
if _gm := re.match(r'/goal(?:\s+([\s\S]*))?$', raw_query.strip()):
    kickoff = self._handle_goal_command(_gm.group(1) or '', display_queue)
    return kickoff if kickoff else None
```

   - `status / clear / error` 仍返回 `None`（本地结束，不空转回合）。
   - 只有 `set` 返回字符串 → `run()` 继续走 UserPromptSubmit + 模型回合。

2. `_handle_goal_command()` 的 set 分支：
   - 保留 `_set_goal()` 与写 history 的 `[SYSTEM]` 提示；
   - 把终结性 `{'done': ...}` 改为**非终结性** `{'system': 'Goal set: ...'}`，
     避免前端把设置动作当作回合结束；
   - 返回 CC 同义 kickoff 文案，交给模型回合。

3. history / kickoff 文案对齐 CC `qVn`（"A session-scoped Stop hook is now active..."）。

4. `__init__` 增加 `self._workflow_launched_this_turn = False`（回合边界复位，
   供 workflow 延迟求值使用，配合既有 defer 逻辑）。

### 3.2 前端消费非终结性 `system`

- `frontends/ink/bridge.py::_consume_display_queue`：识别 `"system"` 键，
  发 `{"type":"system","text":...}`，并继续等待模型 `done`。
- `frontends/terminal/tuiapp.py`：新增 `_on_system_notice()`，把该提示作为
  系统消息追加，不结束回合。
- `app.py` 的 CLI 交互循环：识别 `item['system']` 并打印。

> 单通道原则：`display_queue` 是唯一投递通道。`_handle_goal_command` 里
> **不再**同时 `hook_emit`，否则 Ink 会重复显示两次 "Goal set"。

### 3.3 测试

- `tests/test_goal_phase0.py`：`_run()` 兼容 kickoff 返回值；
  断言 set 为非终结 `system` + 返回 kickoff；新增 `/goal` 路由进模型回合的回归用例。
- 真实 LLM 回归脚本（新增，放 `tests/`）：
  - `tests/real_goal_slash_kickoff_e2e.py`（单条 `/goal` 必须真跑一轮并建文件）
  - `tests/real_goal_slash_8queens_e2e.py`（用户原始 8 皇后场景，校验棋盘是合法解）
