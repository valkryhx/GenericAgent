# 工作流执行契约语义化验收改造实施方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 GA workflow execution contract 从“必须逐字调用计划工具”改造成“能力声明 + workspace ACL + 必要来源证据 + artifact 语义验收”，避免 DOCX 等复杂产物因合法实现路径不同而被误判失败。

**Architecture:** `requiredTools` 表示 agent 可使用的能力；`requiredToolEvidence` 只有显式 `mode=required` 时才是阻塞门禁，默认对本地文件写入工具使用 preferred 语义；artifact contract 负责文件存在、路径安全、readback 和类型结构验收。外部来源工具（如 Tavily）继续保持逐 agent 的 required provenance evidence。`code_run` 只能在 workspace ACL 内写入，不能绕过路径和产物检查。

**Tech Stack:** Python 3.10+、标准库 `unittest`、workflow planner/controller/runtime、Node workflow worker、真实 DeepSeek + Ink UI E2E。

---

## 背景与证据

真实任务“5 个 subagent 搜索 OpenAI 利用 GPT 解决数学猜想的新闻，交叉验证并生成 DOCX”中，Document Writer 使用 `code_run + python-docx` 成功生成了约 41.8 KB 的 DOCX，并通过 Python 读取验证；GA 只因为没有看到逐字的 `file_write` 调用而拒绝运行。Step-Code 使用 tool profile、writable ACL、artifact/evidence 路径和 runtime 结果校验，没有 `requiredToolEvidence` 的逐工具硬匹配契约。

因此本改造保留必要的 provenance 门禁，但不再把单一工具名等同于任务完成条件。

## 契约语义

### 工具能力

```json
"requiredTools": ["file_write", "file_read", "code_run"]
```

表示 agent 可使用或可能需要的工具能力，不自动要求每个工具都被调用。

### 工具证据

```json
{
  "tool": "mcp__tavily__tavily_search",
  "agent": "Search Agent 1",
  "minimumCalls": 1,
  "mode": "required"
}
```

`mode` 取值：

- `required`：缺失即失败；用于 Tavily 等来源真实性关键工具。
- `preferred`：记录缺失，但不阻塞；用于普通本地写入工具。
- `informational`：只记录统计，不参与验收。

对历史计划保持兼容：未声明 mode 时，MCP 工具默认 required；`file_write`/`file_patch` 默认 preferred，避免旧 planner 对 DOCX 产生错误硬门禁。

### Artifact 验收

artifact 的阻塞条件来自：

- 路径在 workspace 内；
- `artifact_exists`；
- `artifact_readback`；
- 可选的 `artifact_structure`、`docx_structure`、`html_structure`、`json_schema`。

允许的写入实现包括 `file_write`、`file_patch`、`code_run`。`code_run` 仍受 workflow workspace 和 writable ACL 约束，不能通过路径逃逸获得成功。

## 完成标准

1. 普通 artifact writer 不会因未调用某个单一写入工具而被误拒绝。
2. Tavily 等来源真实性关键工具仍有逐 agent 的 required evidence。
3. `code_run` 不能越过 workspace ACL、artifact 路径检查或 readback 检查。
4. DOCX 的合法 `python-docx` 生成路径可以通过 artifact 语义验收。
5. 真实 Ink workflow 任务完成并回到 idle。

## 设计结论

通用 workflow runtime 不应猜测 DOCX、HTML、PDF、图片或其他生成物的“正确内容”。参考 Step-Code 的能力/ACL/运行时边界，GA 将产物验收分层：存在性、路径安全、声明的回读证据属于宿主硬契约；内容结构和来源数量属于任务专属验证，只有计划明确声明严格检查时才阻塞。这样既保留安全与可审计性，也避免模型合法生成物因格式或表达方式不同被误判。
