## 1. 本轮结论

GA 已经具备一套可运行的本地 hooks 基础实现：

- 33 个 CC 303 事件名已完整进入配置合同；
- 5 类用户可见 handler 均有执行入口：`command`、`prompt`、`agent`、`http`、`mcp_tool`；
- `command` 已跑通真实子进程、JSON stdin、stdout、exit code、timeout 和审计；
- `prompt` / `agent` 使用隔离的 tool-free prompt runner，并已覆盖普通文本与 JSON 输出；
- `http` 使用 POST JSON、env 白名单 header 插值，并区分 guard 与非 guard 的失败语义；
- `mcp_tool` 支持 `mcp__server__tool` 解析和递归 `${path.to.field}` 插值；
- `Stop` 已绑定到用户回合终态，而不是 GA 内部 `Turn N`；
- `SubagentStop` 与主会话 `Stop` 已分流，避免 workflow fan-out 重复 beep；
- workflow child 使用 job-scoped hook proxy，不共享主 agent history；
- Ink 增加 `/hooks` 只读面板、`hooks_status` 轻量协议和 slash suggestion；
- 已接入 `SessionEnd`、`PreModelSwitch`、`PostModelSwitch`、`PreCompact`、`PostCompact` 等本地生命周期。

## 6. 安全边界

工具调用顺序保持为：

```text
capability -> permission -> PathACL -> PreToolUse
-> updatedInput 后重新 PathACL -> execute
```

关键规则：

- `PreToolUse` hook 只能收紧权限，不能放大 GA 原本拒绝的能力；
- hook 的 `updatedInput` 修改路径后，必须重新跑 PathACL；
- `deny` 会发出 `PermissionDenied`，且工具不执行；
- guard 类事件失败可 fail-closed，通知型事件不因 hook 错误阻塞主流程；
- HTTP header 只插值 `allowedEnvVars` 中列出的环境变量；
- 审计日志会经过现有 `sanitize()`，避免 token / authorization 泄漏。

## 7. 多 agent 作用域

workflow child 不再直接共享主 `GenericAgent` 作为 hook parent，而是构造 job-scoped proxy：

```text
agent_id   = <runId>:<jobId>
agent_type = workflow_child
task_dir   = child workspace
session_id = leader session id
```

只共享：

```text
hook_runtime
hook_emit
```

不共享主 agent 的 history、可变 task_dir 和当前 turn 状态。这样 `SubagentStop`、审计和 per-job 输出不会串到 leader。

### 9.2.1 生命周期边界（2026-10-20 补测）

`Stop` 与 `SessionEnd` 是两个不同层级，不能按 GA 的 `Turn N` 直接映射：

```text
UserPromptSubmit   一个用户请求进入，1 次
  Turn 1           LLM/tool 内部迭代
  Turn 2           LLM/tool 内部迭代
  Turn 3           最终 assistant 正文
Stop                同一个用户请求结束，1 次
SessionEnd          真正退出 Ink 会话或 /new，另计
```

回归证据：

- `tests.test_hooks_lifecycle.HooksLifecycleTests.test_stop_fires_once_after_three_internal_llm_turns`
- `tests.test_hooks_lifecycle.HooksLifecycleTests.test_configured_stop_hook_runs_once_after_three_internal_llm_turns`
- `tests.test_ink_bridge.InkBridgeTest.test_session_end_is_emitted_once_even_if_stop_is_repeated`
- `tests.test_ink_bridge.InkBridgeTest.test_new_session_emits_session_end_before_replacing_agent`
- `tests.test_ink_bridge.InkBridgeTest.test_stop_aborts_running_agent`
- `tests.test_ink_bridge.InkBridgeTest.test_jsonl_stop_command_aborts_turn_without_session_end`

判定含义：Ink `/stop` 或 Esc 走 `bridge.abort_current_turn()`，只中止当前用户请求；随后 `GenericAgent.run()` 的收尾仍对应 `Stop`，不会发 `SessionEnd`。真正关闭会话走 `shutdown`/Ctrl+C/`/quit`/`/exit` → `bridge.stop()` → `SessionEnd(reason=exit)`；`/new`、`/reset` → `new_session()` → `SessionEnd(reason=clear)`。因此“多个 turn 之后才 stop”在 CC/GA 中指的是：**同一个用户回合内部可经历多个 LLM/tool turn，最后只在该用户回合结束点触发一次 Stop**；如果用户真的关闭会话，则再触发一次 SessionEnd，而不是用 SessionEnd 替代 Stop。

### PermissionRequest：已接线

`PermissionRequest` 现在在 `GenericAgentHandler._dispatch_impl()` 的 `mode_policy ask` 分支执行：

```text
ask -> PermissionRequest hooks
  -> allow: nested decision.updatedInput -> PathACL -> skip user prompt
  -> deny: PermissionDenied -> tool not executed
  -> no verdict: existing PermissionRuntime user approval
```

实现必须读取 CC 的嵌套结构：

```json
{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow","updatedInput":{}}}}
```

因此 `HookResult.permission_behavior` / `permission_message` 从 `decision` 读取，`HookAggregate.add()` 同时合并 `decision.updatedInput`。`PermissionRequest` 仍不能绕过 capability、已有 deny 规则或 PathACL。

### HTTP 安全门禁：已完成本轮 P1

- `allowedHttpHookUrls`：未定义=全放行，空数组=全禁，支持 `*`；请求前判定；

- `allowedEnvVars`：与全局 `httpHookAllowedEnvVars` 取交集；全局未定义时由 handler 声明；
- `/hooks` 面板显示 URL/env policy 与 handler 的 async/async-rewake 标记。
