## 1. CC 的渲染层规则（提炼，详见 CC 证据文档）

1. **图标是具名字形表**（`m0052` / exe @201043800）：工具 bullet `⏺`(macOS)/`●`(其他)、结果前缀 `⎿`、
   星号 `✻`、树形 `├└│`、圆角框 `╭╮╰╯`、折叠三角 `▸`、箭头 `↑↓→`。
2. **工具调用行** = `⏺ ToolName(摘要)`。
3. **工具结果行** = `  ⎿  <内容>`，**整体 dim**；内容再缩进（`paddingLeft:3`）。
4. **折叠** = `Hj({lock:"offscreen"})` 渲染后测高、`minHeight` 锁定 + `overflowY:hidden`；
   提示文案走**动态键位** `(ctrl+o to expand)`，`ctrl+e` = 全部展开/收起。
5. **spinner** = 字形帧 `· ✢ ✳ ✶ ✻`（回弹）+ ~190 个随机动词 + `(esc to interrupt)`；
   「思考中」另起一行 `✻ Thinking…`（dim + italic）。
6. **大量用 dim（变暗）而非换色**表达「次要信息」。

## 2. GA 现状 vs CC（差距）

| 维度 | GA 现状 | CC | 差距 |
| --- | --- | --- | --- |
| 工具调用 bullet | `> ToolName(args)`（ASCII `>`） | `⏺ ToolName(args)` | 审美；且 `>` 与 user 消息 `>` 撞车 |
| 工具结果前缀 | 无专用前缀（混在 `[Action]/[Status]` 文本里） | `  ⎿  ` + dim | **缺** |
| 图标 | emoji（`🛠️` `🔨` `📥` `✅`）+ 少量 unicode | 统一字形表 | **审美偏低** |
| 折叠 | `expandedTools` 全局开关（ctrl+o）+ `(ctrl+o to expand)` 提示 | 全局转录 + per-block offscreen 锁 | 有开关，**无 per-block 折叠** |
| 折叠提示 | 硬编码 `(ctrl+o to expand)` | 动态键位 | 可接受（GA 键位固定） |
| spinner | `✻ <Verb> (12s · ↑… ↓… Σ…)`（`activityStatus.ts`） | 帧动画 + 动词 + esc | 已有雏形；无帧动画 |
| workflow 详情 | `Phases │ Agents` 两列表 + `left | right` | 树/盒 | **对齐生硬**（固定 pad） |

## 3. 实施方案（分步，按性价比）

   `pointer` / `triangleRight` / `triangleDown` / `check` / `cross` / `pending` / `warn` /
   `arrowUp` / `arrowDown` / `treeBranch` / `treeLast` / `treePipe` / `box` …）。

   - 工具调用：`> name(args)` → `⏺ name(args)`（bullet 用 `glyphs.bullet`）。
   - 新增**工具结果行**渲染：`  ⎿  <内容>`；多行结果后续行缩进对齐到前缀之后。
   - `(ctrl+o to expand)` 提示保留，但用字形常量拼。

### 5.1 源码去 emoji（2026-10-16，commit 759d991）

用户要求「这些 emoji 很不规范，要在**源码里**改，不要只在 UI 层归一」——即让 GA agent
**直接产出** CC 字形，而不是让 ink 渲染层去翻译。据此把 GA 源码里的工具头/状态 emoji
替换为 CC 字形（对齐本仓库 §2.1 字形表）：

| 语义 | 旧（GA 源码） | 新（CC 字形） | 落点 |
| --- | --- | --- | --- |
| 工具调用头 | `🔨 Tool: \`x\`  📥 args:` / `🛠️ Tool: …` | `⏺ Tool: \`x\` args:` | `agent_loop.py` / `continue_cmd.py` |
| 工具紧凑行 | `🔨 x(args)` | `⏺ x(args)` | `agent_loop.py` |
| 成功哨兵 | `✅` | `✓` | `ga.py` / `agentmain.py` / `continue_cmd.py` / `chatapp_common.py` / `btw_cmd.py` |
| 失败哨兵 | `❌` | `✗` | 同上 |

**关键坑（协议哨兵）**：`✅` 在 GA 里不只是显示，还是**协议哨兵**——多个前端用
`str(result).startswith("✅")` 判定 `/continue` 恢复是否成功（`ink_bridge.py`、`stapp.py`、
`tuiapp_v2.py`、`dcapp.py`）。因此**不能只替换字面量**，必须把哨兵判断改成**元组**：
`startswith(("✅", "✓"))`——既认新 `✓`，又向后兼容旧 `✅`。`App.tsx` 的 resume 前缀正则
同步改为 `^[✅✓]\s*`。这正是 ink-ui 测试一开始 `KeyError: 1` 的根因。

**测试**：pytest（`test_ink_bridge` / `test_code_run` / `test_continue_cmd_resume` /
`test_agent_loop_parallel_tools`）**160 passed**；ink-ui `npm test` **427 passed**；
`tsc --noEmit` 通过；`grep -rn "🔨\|🛠\|📥"`（排除 `temp/`）**无残留**。
