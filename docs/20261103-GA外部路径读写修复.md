# GA 用户指定外部路径读写修复：主 agent 硬限制 + 子 agent pathRoot 软提示

日期：2026-11-03
关联：`456b529`（workflow 工作区外 deliverables 启动失败修复）、`94a1022`（真实 LLM 测试策略）
模型：`default/deepseek-v4.1-flash`（`llm.yaml` profiles.default）

## 1. 结论先行

用户要求“指定具体路径必须支持读写”。复测发现两处真问题，均已修复并用真实 LLM 验证：

1. 主 agent 被错误关进项目根（代码 bug，影响最大）。
2. workflow 子 agent 的 pathRoot 软提示无条件把绝对路径改写回 workspace（提示词 bug）。

修复后真实 LLM 复测：18/18 PASS（主 agent 外部读/写/嵌套 + bash code_run +
workflow 两个子 agent 外部绝对路径落盘）。

区分：GA_PROJECT_ROOT=D:\目标 是把目标目录设成“项目根”，这条路一直可用；本次修复的是
不改变项目根、从仓库 A 启动仍能读写项目外任意目录 B 的能力。


## 2. 问题 A：主 agent 被 workspace_root 限制

### 现象
从仓库根（项目 A）启动，让主 agent 读写外部绝对路径 D:/test_ga_paths_verify/<stamp>/seed.txt，
模型打印 [PathACL] deny: file_read；而同一次运行的 workflow 子 agent 却能读写同一外部目录。

### 根因
genericagent/core/app.py 构造主 handler 时传了 workspace_root=project_root。该参数本是
workflow 子 agent 的硬沙箱概念，在 handler 内同时承担两件事：
- _check_workspace_path_access 激活 PathACL，任何项目外绝对路径被拒；
- do_code_run / code_run 进入 workspace 分支，非 Python（bash/powershell）被直接拒绝。
源自 963c09f（项目目录改造）沿用至今；PathACL 在 d6d2a73 接入后对主 agent 也生效。

### 修复
新增 build_main_handler(agent, history, tool_cwd)，主 agent 不传 workspace_root。
语义 = unrestricted 子 agent：tool_cwd 锚定相对路径，绝对路径可指向 OS 允许任意位置。

## 3. 问题 B：子 agent pathRoot 软提示改写绝对路径

### 现象
GA_WORKFLOW_WORKSPACE_ROOT=TARGET 时，子 agent 应把 alpha.md/beta.md 写到 TARGET/wf/，
实际 alpha.md 被写到 TARGET/workflow-runs/<run>/wf/alpha.md。job 仍 succeeded（deliverables
是 advisory），但产物落错目录。

### 根因
genericagent/workflow/child_agent.py::_build_prompt 的 pathRoot 文案无条件写死
“workspacePath wins，绝不写任务里冲突的绝对路径”。即使 pathPolicy=unrestricted 也照此，
模型于是把绝对目标改写回 workspacePath。

### 修复
pathRoot 按 pathPolicy 分支：
- workspace：保留严格单根 + 明确“外部绝对路径被拒绝”；
- unrestricted：相对路径锚定 workspacePath，任务给出的绝对路径必须原样使用。


## 4. 验证（真实 LLM，过程断言优先）

测试脚本：tests/real_main_agent_outside_path_e2e.py（外部目录 D:/test_ga_paths_verify3/<stamp>，
不设 GA_PROJECT_ROOT，从仓库根启动 = 项目 A）。结果 18/18 PASS：
- 主 agent：file_read 外部 seed 取 token；file_write 新建 a/b/hello.txt，内容含 HELLO_EXT + 外部 token；
- 主 agent：code_run(type=bash) 在外部目录生成 bash_out/marker.txt（BASH_OK）；
- 全程 0 次 PathACL deny；
- workflow：alpha/beta 两 job succeeded、token>0，均写到外部绝对目录 TARGET/wf/，
  beta 读到外部 seed token（alpha 不再被改写进 workflow-runs）。

关键断言不是“看起来跑完”，而是：真调用了 file_read/file_write、文件真实落在外部目录、
内容含外部 token、每个 job output_tokens>0、流里没有 PathACL deny / only permits Python。
