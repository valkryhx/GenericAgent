# GA 提示词与工具使用优化（第 1 轮）：让专用工具和 skill 真的被用起来（2026-11-10）

> 用户反馈：GA 很少用最近从 CC 借鉴的 bash / glob / grep 类工具，也很少调用 skill，
> 怀疑提示词太老。核心目标：把 GA 的复杂任务与代码任务能力提上来，分多轮推进。
>
> 本轮的结论是：**提示词确实缺一层"工具选择纪律"，但更硬的瓶颈在分发和工具质量**——
> 不先把这两件事修好，提示词写得再强硬也只会让模型去用不存在的工具或 20 秒才返回的工具。
> 本轮不碰子智能体 / 多智能体 / workflow 的专用提示词（只动共享 base prompt 的通用段落）。

---

## 0. 结论先行

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 打包 schema 的工具数 | 32（**无 file_glob / file_grep**） | 34（与仓库 `assets/` 一致） |
| 本机安装版用户数据 schema | 31（旧副本，永远不会更新） | 托管刷新机制修复（新装/升级路径），旧副本可用 `GA_REFRESH_ASSETS=1` 强制修 |
| base prompt 是否提 file_glob / file_grep | 完全不提 | 明确的"专用工具优先，shell 兜底" |
| skills 段落 | 一句话 + 列表（且首条与说明粘在一行） | 主动扫描 + 部分相关即加载 + 列表独立成行 |
| `file_grep` 在真实仓库全仓搜索 | **19.6 s**（Python 全树扫描，含 gitignore 的 temp/） | **46 ms**（ripgrep，跳过 `.ga`/`.worktrees`） |
| 代码检索任务里的 `code_run` 调用 | 2 次（含一次手写正则脚本绕开专用工具） | **0 次** |
| 同一检索任务耗时 | 192.8 s | 19.6 s |

## 1. 先证据，再改提示词

### 1.1 模型其实会用专用工具——前提是工具真的在列表里

用真实模型（`zhanlu-ds/moma/deepseek-latest-flash`）在**当前仓库、当前提示词**下跑两个代码检索任务
（探针：`temp/prompt_ab_probe.py`，进程内真实 Agent，记录每次 tool call）：

```text
turn 1: 192.8s  {file_grep: 4, code_run: 2, file_read: 2}
turn 2:  13.6s  {file_grep: 2, file_glob: 1, code_run: 1}
```

也就是说：**能用的工具它是会用的**。真正的断点在两处。

### 1.2 断点一：分发断裂——安装版根本看不到 file_glob / file_grep

| 位置 | 工具数 | 有 file_glob/file_grep？ |
| --- | --- | --- |
| `assets/tools_schema*.json`（源码仓库运行时） | 34 | ✅ |
| `genericagent/resources/assets/tools_schema*.json`（**打包副本**） | 32 | ❌ |
| `%LOCALAPPDATA%\GenericAgent\assets\tools_schema.json`（本机安装版运行时） | 31 | ❌ |

两处机制叠加：

1. 提交 `0344f94 feat(tools): 补齐内置工具集` 只改了根 `assets/`，没有同步打包副本；
2. `paths.ensure_runtime_assets()` 原来只**补缺失**（`_copy_tree_missing`），用户数据目录一旦播种过，
   后续任何内置资源修复都到不了已有安装——所以本机的 schema 永远停在 31 个工具。

### 1.3 断点二：`file_grep` 太慢，模型只能退回 shell

真实仓库全仓 `files_with_matches` 查询：

```text
修复前: 19635 ms  engine=python   （全树 walk，把 gitignore 的 temp/ 日志也扫了）
修复后:    46 ms  engine=rg       （ripgrep，跳过 .ga/.worktrees）
```

`glob_files` 早就有 rg 快路径，`grep_files` 没有；而且忽略目录集合缺 `.ga`、`.worktrees`
（GA 自己的运行时目录 / 整份源码副本）。基线里模型第一次 grep 就被噪音淹没，随后写了一段
`subprocess + 正则` 绕开专用工具——**这不是模型不听话，是工具让它没法用**。

## 2. CC 319 的做法（源码坐标）

| 规则 | CC 319 原文（节选） | 坐标 |
| --- | --- | --- |
| 专用工具优先 | `Prefer dedicated tools over ${S} when one fits (${w}) — reserve ${S} for shell-only operations.` | `m0591_0x11be624e.js:109943`（`# Using your tools`） |
| Bash 工具自身的免责声明 | `IMPORTANT: Avoid using this tool to run ${N} commands ... Instead, use the appropriate dedicated tool ...` | `m0591_0x11be624e.js:77023` |
| 质量纪律（不做多余抽象 / 兜底 / 注释） | `Don't add features, refactor, or introduce abstractions beyond what the task requires...` / `Don't add error handling, fallbacks, or validation for scenarios that can't happen.` | `m0591:109906`（`# Doing tasks`） |
| 交付准确性 | `be accurate about what you verified vs. what you assumed` | 同上 |
| 代码位置引用 | `include the pattern file_path:line_number` | `m0591:109999`（`# Tone and style`） |
| skill 列表与点名 | `The following skills are available for use with the Skill tool:` / `When the user types /<skill-name>, invoke it ... Only use skills listed` | `m0591:228783` / `m0591:109935-109943` 区段 |

GA 的 base prompt 原来只有"按 do_<tool_name> 分发 + 以工具列表为准"，没有选择纪律；skills 只有一句
"命中 Available Skills 时先 load_skill"。

## 3. 本轮改动

### 3.1 base prompt（zh + en，`assets/sys_prompt*.txt`，各 67 → 75 行）

`# 工具使用` 新增：

```text
- 工具选择（专用工具优先，shell 兜底）：找文件 / 目录用 file_glob；找内容用 file_grep
  （先用 output_mode=files_with_matches 收敛范围，再用 context 看上下文）；读文件用 file_read
  （start / count / keyword 分页）；写改文件用 file_write / file_patch。
- 只有 shell 才能做的事才用 code_run：跑测试、构建、git、包管理、启动服务，或执行没有专用工具的
  脚本。不要用 code_run 重写 find / grep / ls / cat 这类已有专用工具的操作。
- 检索结果太多时先缩小 path 或加 glob 过滤；不要被噪音淹没后改用 code_run 写正则脚本绕开专用工具。
- 一轮里可以并行发多个互不依赖的调用（多次读、多次搜）；有依赖的必须串行，不要先猜后补。
```

skills 那条替换为：

```text
- 开工前先扫一遍 Available Skills：只要某个 skill 与任务领域、仓库、流程或产物形态部分相关，
  就先 load_skill 读全文再动手；不要因为“大概知道怎么做”跳过——skill 里是本项目验证过的步骤、
  坑和验收标准。用户用 /<skill-name> 点名时必须 load_skill，且只用列表里出现过的名字。
```

`# 代码与改动纪律` 新增三条（来自 CC `# Doing tasks`）：不为不可能场景加兜底/重试/兼容层、
不引入任务之外的抽象（三行重复优于过早抽象）、优先改现有文件。
`# 沟通与交付` 新增：引用代码位置写 `文件路径:行号`。

英文版逐条对应（`assets/sys_prompt_en.txt`）。

### 3.2 skills 段落（`genericagent/core/skills.py`）

- 修复格式 bug：说明句结尾是空格，直接和第一条 skill 粘在一行
  （`...before following it. - workflow-authoring: ...`），最显眼的那条看起来像半句话；
- 措辞改成与 base prompt 一致的"先扫描、部分相关就加载、加载后以 skill 为准"。

### 3.3 工具质量（`genericagent/core/file_search.py`）

- `grep_files` 新增 ripgrep 快路径（与 `glob_files` 同源）：`--line-number/--no-heading/--color never`、
  `--files-with-matches` / `--count-matches`、`--context`、`--glob` 过滤与忽略目录；
  rg 不可用 / 正则语法不兼容 / 非 0/1 退出码时**回退 Python 扫描**（原有行为）；
- `_COMMON_IGNORE_DIRS` 增加 `.ga`、`.worktrees`（GA 运行时与源码副本，噪音来源）；
- 修 Windows 路径：rg 输出 `.\src\app\` 形式，直接 `lstrip("./")` 会留下反斜杠被 pathlib 当作
  盘根相对路径（`D:\src\app.py`）。现在先统一分隔符再逐段剥离。

### 3.4 资产分发（`genericagent/paths.py` + 打包副本）

- 新增 `.bundled-assets.json` 清单，按 sha256 记录"我们写进去的文件"：
  - 缺失 → 复制并记录；
  - 记录且用户没改过 → 内置内容更新时**刷新**（本次修复能到达已有安装）；
  - 记录但用户改过 → 保留；
  - 无记录（旧安装/手工放置）→ 标记为 unmanaged，永不覆盖；`GA_REFRESH_ASSETS=1` 可强制修复。
- `genericagent/resources/assets/{tools_schema,tools_schema_cn,sys_prompt,sys_prompt_en}` 与根
  `assets/` 同步；新增 parity 测试，防止再次漂移。

### 3.5 测试

| 文件 | 覆盖 |

## 4. 真实模型 A/B（zhanlu-ds，同一组提示词）

| 场景 | 改前（baseline） | 改提示词后 | 改提示词 + 工具修复后 |
| --- | --- | --- | --- |
| 代码检索 turn 1 | 192.8 s，8 calls，code_run 2（含手写正则脚本） | 33.2 s，6 calls，code_run 1 | **19.6 s，10 calls，code_run 0** |
| 代码检索 turn 2 | 13.6 s，4 calls，code_run 1 | 8.6 s，4 calls，code_run 2（`git grep`） | **11.5 s，5 calls，code_run 0** |
| archify skill 任务 | 239.9 s，load_skill=archify | — | 199.8 s，load_skill=archify |
| workflow skill 任务 | 55.3 s，load_skill=workflow-authoring | — | 69.1 s，load_skill=workflow-authoring |

读法（如实说明）：

- 单样本、随机模型输出，**不能当成统计显著的结论**；但方向一致：工具修好后模型不再绕开专用工具；
- skill 两个任务在改前就已经正确加载对应 skill（显式触发场景），本轮只保证不退化；
- 检索任务里 `code_run` 归零是本轮最直接的收益。

## 5. 没做 / 下一轮候选

1. **模型"不主动用 skill"的更强证据**：需要一批"隐性匹配"任务（任务不点名 skill，但领域与之相符），
   量化改前改后的加载率；本轮只用显式触发任务验证了不退化。
2. **skills 列表 8KB**：本机 53 个 skill，列表已接近预算上限；下一轮可考虑按 cwd/仓库相关性裁剪或分层。
3. **file_glob 的 rg 路径缺少 `--glob` 与忽略规则的一致性测试**（已有基础用例，但没有逐项对拍）。
4. **子智能体 / team / workflow 专用提示词**：本轮刻意不动；下一轮单独评估它们是否需要
   "工具选择"段落（子代理继承同一份 base prompt，已经自动获益）。
5. **打包资产的历史修复**：旧安装首次运行会把未记录文件标记为 unmanaged（不覆盖），
   需要一次 `GA_REFRESH_ASSETS=1` 才能拿到新 schema；若要全自动，需要额外的"历史哈希"清单。
