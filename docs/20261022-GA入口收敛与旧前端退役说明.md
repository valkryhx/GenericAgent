# GA 入口收敛与旧前端退役说明（2026-10-22）

## 1. 结论

GA 对外的受支持入口收敛为：

```text
ga        # 默认启动 React/Ink 终端 UI
ga ink    # 显式启动 React/Ink 终端 UI
```

`ga cli` 保留为轻量排障 / 纯 Python 对话入口；`ga list`、`ga status`、`ga update` 是管理命令。

以下入口不再属于发布面，代码暂时保留但标记为 deprecated：

| 入口 | 依赖 | 状态 |
| --- | --- | --- |
| `ga gui` / `frontends/desktop/qtapp.py` | PySide6、markdown | deprecated |
| `ga web` / `frontends/web/stapp*.py` | Streamlit | deprecated |
| `ga launch` / `launch.pyw` | pywebview、Streamlit | deprecated |
| `ga tui` / `frontends/terminal/tuiapp*.py` | Textual、rich | deprecated |
| `ga pet` / `frontends/desktop/desktop_pet*.pyw` | pillow、Tk | deprecated |
| `ga hub` / `hub.pyw` | Tk / 多服务编排 | deprecated |
| 各聊天机器人 / ACP / 飞书桌面入口 | 各平台 SDK | deprecated（按需保留源码） |

> 为什么先标 deprecated 而不立即删：`frontends/terminal/continue_cmd.py` 仍被 Ink bridge、机器人适配与测试复用；`frontends/common` 也有共享逻辑。整目录删除会破坏现有可复用能力，也无法满足“全部保留、可回查”的仓库铁律。

## 2. 依赖影响

默认安装不再拉取以下旧 UI 依赖：

- `streamlit`
- `pywebview`
- `textual`
- `rich`
- `pillow`
- `PySide6`
- `markdown`

这些依赖被移动到显式 opt-in extras：

```bash
python -m pip install -e ".[legacy-ui]"
python -m pip install -e ".[legacy-qt]"
python -m pip install -e ".[legacy-bots]"
```

普通用户只需：

```bash
python -m pip install -e .
npm install --prefix frontends/ink/ui
```

`mcp` 和 `langfuse` 仍是独立可选能力：

```bash
python -m pip install -e ".[mcp]"
python -m pip install -e ".[langfuse]"
```

## 3. CLI 行为

旧命令仍然可以被识别，但不会启动对应进程，而是输出明确提示并以退出码 `2` 结束。例如：

```text
$ ga tui
[DEPRECATED] tui: Textual TUI 已过时，请使用 `ga ink`；仅需兼容时安装 `.[legacy-ui]`
```

`ga list` 只显示受支持入口，不再宣传 legacy UI。

## 4. 打包建议

发布包应只包含：

```text
ga_cli/
genericagent/
frontends/ink/bridge.py
frontends/ink/ui/          # 预构建产物或必要运行依赖
genericagent/workflow/js/  # worker.js + script_contract.js
assets/                    # 运行时必需资源
skills/ memory/            # 首次启动模板或必需内容
```

发布包不应默认包含：

```text
frontends/desktop/
frontends/web/
frontends/terminal/tuiapp*.py
frontends/bots/
launch.pyw
hub.pyw
frontends/skins/
```

> 注意：如果未来仍有机器人 / ACP 需求，应单独出可选插件包，而不是塞回主安装包。

## 5. 后续彻底删除的检查清单

若确认完全不需要旧入口，再按下面顺序删除，避免一次删太多导致不可定位的问题：

1. 迁移 `frontends/terminal/continue_cmd.py`、`btw_cmd.py`、`export_cmd.py` 中仍被 Ink bridge 复用的能力（至少 `continue_cmd` 仍被引用）。
2. 删除仅属于旧 TUI 的测试文件，或把它们改为测试迁移后的公共模块。
3. 再删 CLI 的 `DEPRECATED_COMMANDS` 兼容分支和对应测试。
4. 删除旧 UI 源码目录、`launch.pyw`、`hub.pyw` 与 `legacy-*` extras。
5. 清理文档中的旧入口说明。
6. 复跑 Python 全量测试、Ink Python bridge 测试与 Ink `npm test`。

本轮**没有删除源码文件**，只完成了入口收敛和依赖隔离；这是为了保持可回查、可回滚，并遵守项目“全部保留、不要一次性删减”的约束。

## 6. 当前验证基线

- `python -m ga_cli list` 只显示 `ink` 与 `cli`。
- `ga tui` 返回 deprecated 提示与退出码 2。
- `tests.test_ga_cli_launcher` 覆盖默认 Ink、两个入口、旧命令不暴露。
- `pyproject.toml` 不再声明旧 UI 为默认依赖。
