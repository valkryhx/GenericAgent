> 日期：2026-10-30
> 前置：阶段 0/1/2-A/4/5 已完成；Phase 6 隐性缺口已修（`32c9a2a`/`89f123d`）。
> 目标：给 goal 补"无用户消息时也能自动把模型叫起来继续"的能力（2-B 定时 check-in、3 中断自动重试）。
> 关联：`docs/20261028-GA-goal模式设计与实施方案.md` §7/§8、`docs/20261030-GA-goal落地进度与阶段2-3决策.md` §7。

## 0. 一页结论

- **不是从零造轮子**：GA 已有 `asyncRewake` 唤醒原语（后台 hook 完成 → `HookWakeRequest` → 前端把一条消息 `put_task` 成新回合）。2-B/3 复用它，只是**触发源**从"后台 hook 完成"换成"goal 定时器到点"。
- **两个真实前置缺口**（必须先补，否则做不对）：
  1. `app.run()` 用 `for chunk in gen:`，**丢失 generator 返回的 `exit_reason`** → 分不清"正常完成 / MAX_TURNS / 用户 abort / 异常"，阶段 3 无从判定要不要重试。
  2. **没有跨前端统一的 wake 入口**：`_handle_hook_wake` 只在 Ink bridge 里有；terminal/web/bots 没有等价物，定时器 `put_task` 出来的 display_queue 没人消费。
- **建议分两期**：先 2-B（只依赖"本轮是否 deferred"这一状态，不依赖 exit_reason），稳定后再 3（依赖 exit_reason 归因）。
- **默认关闭**：`GA_GOAL_WAKE=off` 默认，显式开启才启用，避免"模型自己空转烧钱"。

## 2. 前置缺口（先补）

### 2.1 `app.run()` 丢失 `exit_reason`（阶段 3 的硬前置）

`core/app.py:1669` `for chunk in gen:` 只取流式文本，generator 的 `return exit_reason` 被丢弃。
阶段 3 需要按"结束原因"决定是否重试（CC `Yp()`：`retry` / `pause` / `stop` / `none`）。

修法：用 `try/except StopIteration as stop:` 或 `yield from` 捕获返回值，得 `loop_exit = stop.value`（形如
`{'result': 'CURRENT_TASK_DONE'|'MAX_TURNS_EXCEEDED'|...}`），结合 `self.stop_sig`、异常分支，归因为
`completed / max_turns / user_abort / error`，落到 `handler` 或 `self` 上一个 `last_loop_exit` 字段供 goal 判定。

> 影响面：只新增"读取返回值"，不改 `agent_runner_loop` 的生成行为；现有 `is_running/stop_sig` 语义不变。

### 2.2 跨前端 wake 入口缺失

`_handle_hook_wake` 只有 Ink bridge。terminal(TUI)/web/bots/acp 都没有"goal 唤醒器"。
- terminal `frontends/terminal/tuiapp_v2.py:1504` 自己 `put_task` + `_consume_display_queue`，可加一个 goal 唤醒回调。
- web `stapp2.py` 是事件流式消费，需确认是否支持后台起新回合（可能需降级为"只发提示，不自动跑"）。
- bots/acp 同理，**非目标**：明确记为"仅提示，不自动追"。

**统一抽象**：在 `core/goal_wake.py` 定义一个 `GoalWakeScheduler`，持有 `wake_callback: Callable[[str], bool]`（由各前端注入，签名同 `put_task` 包装），核心逻辑与前端解耦。

## 3. 核心组件：`core/goal_wake.py`

```
class GoalWakeScheduler:
    # 每个 session 一个实例，挂在 agent 上（agent.goal_wake）
    # 状态：pending_timer, kind('checkin'|'retry'), due_at, count, session_id, goal_set_at
    def arm_checkin(agent, delay)       # 2-B
    def arm_retry(agent, delay, cause)  # 3
    def cancel(agent, reason)           # 用户新消息/清目标/会话切换/关停
    def fire(agent)                     # 到点：校验 session & goal 未变 → wake_callback
```

- **到点校验（防串台/防过期）**：`fired` 前检查 `agent.session_id == 记录的值` 且 `agent.active_goal.set_at == 记录值`（对齐 CC `zi()`）；任一变化即弃。
- **单飞**：同一 session 同时只允许一个 pending timer（新 arm 先 cancel 旧的）。
- **取消时机**：用户 `put_task(source='user')`、`/goal clear`、goal 达成/失败清空、`/new`、会话 resume、程序关停。
- **遥测**：`goal_checkin`（fired/plan_failed/arm_failed/idle_cap_reached）、`goal_interruption`（fired/gave_up/paused/fire_failed）。

## 4. 阶段 3（先做，较独立）：中断自动重试

**触发**：一次用户回合结束（`app.run` finally 前）且 `active_goal` 仍存在，按 `loop_exit` 归因：

| 归因 | 处理 |
| --- | --- |
| `completed` 且本轮已求值（met/not_met 都已记账） | 清 streak，不重试 |
| `completed` 但本轮 `goal_defer`（后台在跑） | 交给 2-B 的 check-in |
| `user_abort`（用户按停止） | **不自动重试**（尊重用户意图，CC 也是 stop 类清 streak）；仅记录 |
| `max_turns` / `error`（API/模型/工具异常） | 进入 retry：streak+1，按 `Us[retry]` 排 timer，到点 `put_task('Goal check-in: continuing after the last turn ended early ...')` |
| `retries >= 3` | 记 `gave_up`，发一条 system 提示"Goal paused after 3 automatic retries · {cause} · send a message to continue"，不再自动 |

- streak 存 `sessionScratch` 等价物：`agent._goal_retry_streak = {goal_set_at, retries, announced}`，随会话/working_state 持久化（resume 后仍生效）。
- 抖动：`delay = Us[retry] * (1 + 0.1*random)`。
- **非交互会话**（无 wake_callback 的前端）→ 不自动重试（CC 同）。

## 5. 阶段 2-B：deferral 定时 check-in

**触发**：本轮 `run_stop_gate` 判定 `goal_defer=True`（2-A 已有），回合结束后排 check-in timer。

- 首次延迟 `Du=30min`（`CLAUDE_CODE_GOAL_CHECKIN_MINUTES` 覆盖）；退避 `Du*2^min(checkin_count,2)` → 30/60/120。
- 到点 `fire`：若 goal 仍 active 且仍有在途后台任务 → 注入 `Bi()` 文案（列出任务 `- id · type · description`）；后台已清 → 注入 "background work no longer running ... Continue toward the goal."。
- `idle_checkin_count >= 3` → 只重排 tick 不再注入，附 "idle check-ins paused until your next message"。
- 若用户在两次 check-in 之间发消息 → 取消 timer、重置 idle 计数（对齐 CC `swn` 清理 `idleCheckinCount`）。

## 6. 实施顺序（建议）

1. **前置 2.1**：`app.run` 捕获 `exit_reason`（小改，先加测试锁住"完成/abort/异常"三类归因）。
2. **`core/goal_wake.py`**：纯逻辑调度器 + 单测（用 fake clock / fake callback，不打网络）。
3. **阶段 3**：接 `app.run` finally，用 goal_wake 排 retry；Ink bridge 注入 `wake_callback`（复用 `_submit_hook_wake` 改造）。
4. **阶段 2-B**：接 `run_stop_gate` 的 `goal_defer`，排 check-in；同样走 goal_wake。
5. **前端**：Ink 全量；terminal 补 consume + callback；web/bots 仅提示（非目标）。
6. **真实 LLM 自测**：见 §8。

## 8. 测试矩阵

- 单测（无网络）：`goal_wake` 的 arm/cancel/fire 去重、session/goal 变更丢弃、退避与 idle 上限、retry 归因表。
- `app.run` 归因：脚本化 generator 返回 `MAX_TURNS_EXCEEDED` / 抛异常 / `stop_sig` → 断言 `loop_exit` 三类正确。
- 真实 LLM（deepseek-v4.1-flash）：
  - 重试：设置 goal → 人为让 provider 报错一次（或用 monkeypatch 模拟 API error）→ 确认 1 次后自动起新回合且 goal 仍在；连续 3 次后 `gave_up` 文案。
  - check-in：设置 goal → 触发一次 defer（真实在途子 agent）→ 把 `GA_GOAL_CHECKIN_MINUTES` 调到 0.02min 验证到点注入、idle 上限。
- 回归：goal 全量 + hooks + transcript/resume；前端全量。

## 9. 风险与红线

- **烧钱/自跑**：默认 off；有 idle 上限、retry 上限、单飞、到点校验；任何异常 fail-closed（不唤醒）。
- **尊重用户意图**：用户主动 abort / 发新消息 → 立刻 cancel，绝不自动复活。
- **会话隔离**：唤醒必须校验 session_id + goal_set_at，防止旧会话唤醒串到新会话（复用 Ink `_handle_hook_wake` 的 session 守卫）。
- **不改** 静态 Stop（beep）与 2-A 的 defer 语义。
